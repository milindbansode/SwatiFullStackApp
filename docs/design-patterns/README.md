# Design Patterns

This folder keeps reusable software design ideas separate from framework-specific content.

## Covered patterns

1. **Factory** - centralize object creation rules.
2. **Builder** - create complex objects step by step.
3. **Adapter** - isolate external integrations behind a stable internal interface.
4. **Decorator** - add logging, caching, or metrics around existing services.
5. **Strategy** - switch business rules without changing callers.
6. **Observer / Publish-Subscribe** - react to events with loose coupling.
7. **Repository** - abstract data access where it improves domain clarity.
8. **CQRS** - separate write models from read models when the needs differ.
9. **Mediator** - route commands or queries through focused handlers.

## Practical usage

These patterns are intentionally explained with enterprise examples so a senior developer can map them to API, UI, integration, and reporting problems. Extend this folder with code snippets when you want deeper reference material.
